# robotframework-harness 1.0.0

The first release of the Robot Framework agent harness: an Agent Skill, agent hooks and a local live session built on
[robotcode](https://github.com/robotcodedev/robotcode). It is for coding agents that write, debug and repair Robot
Framework tests.

## Install

```bash
cd your-robot-project
uvx robotframework-harness install     # pick your agents: skill, hooks and the runtime in your project environment
uvx robotframework-harness doctor      # proves the hooks fire and a live step works
```

Or through the plugin marketplace (Claude Code, Copilot CLI, VS Code, Codex), pinned to this release:

```bash
claude plugin marketplace add manykarim/robotframework-harness#v1.0.0
claude plugin install rf-harness@robotframework-harness
uvx robotframework-harness install --runtime-only
```

## What is in it

- **Live execution while the agent edits.** New lines of an edited `.robot` file run in a persistent local session,
  with adaptive live timeouts that never reach your files.
- **Evidence-first failure verdicts.** COVERED (with concrete `label:has(#id)` targets), MISSING, IN_IFRAME, SLOW and
  more, plus page-state files (`.rf/state/latest/`) and keyword docs (`.rf/docs/`).
- **Guard rails.** Only certainly-wrong edits are refused, static checks run with robotcode and a Robocop agent profile,
  and the stop gate requires a green plain `robot` run.
- **Per-model output profiles.** Lean for Claude and GPT models, rich for open-weight models.
- **One-command installer.** Plugin or files mode, project or user scope, runtime provisioning, Codex hook trust,
  safe upgrade and uninstall, and `doctor`.

## Supported agents

Claude Code, OpenAI Codex, GitHub Copilot CLI, VS Code (Copilot) and OpenCode. The versions verified for this release
are in the [agent matrix](../agents/matrix.md).

## Evidence

- In same-window A/B runs on live end-to-end journeys, the harness design passed **0.83** of sessions versus **0.69**
  for rf-mcp (206 sessions, round 7).
- The v1 release gate (round 8) compared this package, installed by its own installer, with the measured research
  prototype: **37/45 = 0.82 vs 37/45 = 0.82**, with no per-agent regression.

All data, graders and reports are in [`evidence/`](https://github.com/manykarim/robotframework-harness/tree/main/evidence).

## Known limits

- Desktop (PlatynUI) live steps are opt-in (`RFH_DESKTOP=1`). The guards pass parity tests against rf-mcp, but desktop
  has not been through the live release gate.
- Windows has not been through the live release gate. Marketplace hooks call `python3`, so use `--mode files` there.
- VS Code was verified through install and `doctor` only, as it has no headless session.
- Copilot CLI runs repository hooks only in trusted folders. `doctor` checks this.
- Cursor, Goose, Gemini CLI and Claude Desktop are not supported yet.

- `claude plugin marketplace add manykarim/robotframework-harness#v1.0.0` followed by
  `claude plugin install rf-harness@robotframework-harness` installs plugin version 1.0.0 (isolated Claude config).
- The documentation site and this page are live.
- The release candidate `1.0.0rc1` was published to TestPyPI first and installed from there as a dry run.

## Upgrading from the research prototypes

Prototype installs (`rfharness*` hooks) are detected by the installer. Use `--coexist replace` to remove them.
